## 统一框架

本书论证了分布式训练具有底层的代数结构。理解这一结构——而不是背诵配置——让你能推理从未见过的系统。

### 基础方程

三个方程构成了分布式训练分析的骨架：

**内存方程**（第 19 章）：

$$M = \underbrace{\Psi \cdot b_p}_{\text{parameters}} + \underbrace{\Psi \cdot b_o}_{\text{optimizer}} + \underbrace{\Psi \cdot b_g}_{\text{gradients}} + \underbrace{A(B, S, d)}_{\text{activations}}$$

每种并行策略都是把这一方程在不同 GPU 上做不同的因式分解。

**通信模型**（第 4 章）：

$$T = \alpha + \frac{n}{\beta}$$

每种集合操作都服从这个模型。延迟受限的操作（小 $n$）通过树形算法最小化 $\alpha$ 项。带宽受限的操作（大 $n$）通过环形算法最大化 $\beta$ 利用率。

**计算效率模型**（第 6 章）：

$$\text{MFU} = \frac{\text{Achieved FLOPs}}{\text{Peak FLOPs}} = \frac{6 \cdot \Psi \cdot \text{tokens}}{\text{time} \cdot \text{peak FLOPs}}$$

这揭示了我们在多大程度上真正用上了硬件能力。峰值与实测之间的差距，正是优化所在之处。

### 并行分类法

所有并行策略都在以不同方式回答同一个问题：**你复制什么，又划分什么？**

| 策略 | 划分 | 复制 | 通信 |
|------|------|------|------|
| 数据并行 | 数据 | 模型 | 梯度 AllReduce |
| 张量并行 | 模型（层内） | 数据 | 激活 AllReduce |
| 流水线并行 | 模型（层间） | 数据 | 激活点对点 |
| 专家并行 | 专家 | 路由器、注意力 | token All-to-All |
| 序列并行（Sequence Parallelism） | 序列 | 模型 | AllGather/ReduceScatter |
| 上下文并行（Context Parallelism） | 上下文（注意力） | 模型 | Ring attention |

分布式训练的艺术在于组合这些策略；科学在于预测哪些组合会高效。

### 效率层级

我们学到了一套优化关注点的层级：

```
1. Memory: Can it fit?
   ├── Model states (parameters, gradients, optimizer)
   ├── Activations
   └── Temporary buffers

2. Compute: Is the hardware busy?
   ├── Arithmetic intensity
   ├── Kernel efficiency
   └── Pipeline bubbles

3. Communication: Is the network busy?
   ├── Volume (how much data?)
   ├── Pattern (collective vs point-to-point?)
   └── Overlap (hidden or exposed?)

4. Scaling: Does it improve with more resources?
   ├── Strong scaling (fixed problem, more GPUs)
   └── Weak scaling (proportional problem, more GPUs)
```

调试分布式系统就是沿着这个层级逐层排查。内存问题最先暴露（OOM）。计算问题表现为低 MFU。通信问题在剖析数据中表现为未重叠的集合操作。

## 案例研究的启示

这些案例研究（第 34–36 章）揭示了共同的模式：

### 模式 1：层级匹配硬件

每个成功的系统都把并行层级与硬件层级对齐：

| 硬件层级 | 通信 | 典型并行 |
|----------|------|----------|
| GPU 内 | 共享内存 | 无（串行） |
| GPU 到 GPU（NVLink） | ~900 GB/s | 张量并行 |
| 节点到节点（InfiniBand） | ~50 GB/s | 流水线、数据并行 |

LLaMA 3、DeepSeek-V3 和 Mixtral 都遵循这一模式。张量并行（Tensor Parallelism）留在 NVLink 域内。流水线并行（Pipeline Parallelism）在必要时跨节点。数据并行（Data Parallelism）处理最宽的通信域。

### 模式 2：架构与分布式协同演进

模型架构越来越多地为分布式训练做优化：

- **GQA** 减少 KV 缓存和注意力通信
- **MLA** 为进一步的极端序列长度进一步压缩 KV 缓存
- **稀疏 MoE** 以亚线性激活实现专家并行（Expert Parallelism）
- **滑动窗口注意力** 使注意力内存与序列长度无关

「模型架构」与「系统工程」之间的边界正在消融。DeepSeek-V3 的多头潜在注意力同时是一项 ML 创新和一项系统优化。

### 模式 3：重叠隐藏一切

每个高效率系统都会把通信与计算重叠：

- 前向传播期间 AllGather 参数
- 反向传播期间 ReduceScatter 梯度
- 异步预取流水线阶段
- All-to-All 专家路由与本地计算重叠

目标很简单：**没有 GPU 应该等待网络**。实现很复杂：分桶、流管理和仔细的依赖追踪。

### 模式 4：精度是一个谱系

现代系统策略性地使用多种精度：

| 组件 | 精度 | 理由 |
|------|------|------|
| 前向激活 | BF16 或 FP8 | 计算受限 |
| 反向梯度 | BF16 | 梯度累积（Gradient Accumulation）稳定性 |
| 主权重 | FP32 | 优化器稳定性 |
| 通信 | BF16 | 带宽受限 |
| KV 缓存 | FP8 或量化 | 内存受限 |

DeepSeek-V3 的 FP8 训练表明，即使前向/反向也能在仔细的损失缩放（loss scaling）下使用 8 位精度。

## 调查协议

第 33 章介绍了一种理解任何分布式训练系统的系统化方法：

```
1. Memory Analysis
   ├── Parameter count (by component)
   ├── Optimizer states
   ├── Activation memory (per layer, per micro-batch)
   └── Temporary buffers

2. Compute Analysis
   ├── FLOPs per forward pass
   ├── Arithmetic intensity
   └── Expected MFU

3. Communication Analysis
   ├── Per-collective volume
   ├── Collective count per step
   └── Bandwidth requirement vs. available

4. Scaling Analysis
   ├── Pipeline bubble fraction
   ├── Communication/compute ratio
   └── Efficiency vs. GPU count

5. Validation
   ├── Compare predicted vs. measured
   └── Profile to identify discrepancies
```

这个协议把分布式训练从手艺知识转变为工程实践。把它应用到任何新系统上——在跑第一个实验之前，数字就应该说得通。

## 常见陷阱

多年的分布式训练揭示了一些反复出现的错误：

### 陷阱 1：优化错误的目标

许多团队优化训练吞吐（tokens/second），而他们应该优化的是**质量调整吞吐**（每 GPU-小时的损失）。如果模型收敛慢 30%，20% 的吞吐提升毫无意义。

**解药**：追踪损失曲线，而不只是吞吐。在固定损失目标下比较训练效率。

### 陷阱 2：直到内存爆掉才想起内存

团队常常为计算效率设计并行策略，然后发现内存装不下。

**解药**：先跑内存方程。内存是约束，不是优化目标。

### 陷阱 3：低估通信

互连的理论带宽很少与实测带宽一致。延迟开销、软件栈和集合算法都会降低有效带宽。

**解药**：用真实的消息大小和模式测量实际带宽。按理论最大值的 50–70% 做预算。

### 陷阱 4：过早使用流水线并行

流水线并行会引入气泡（pipeline bubble）。对小模型而言，气泡开销超过内存节省。

**解药**：只有在张量并行饱和 NVLink、且 FSDP 无法把每 GPU 内存降到足够低时，流水线并行才合理。通常这意味着参数 > 30B 的模型。

### 陷阱 5：把可复现性当作事后追加

调试不可复现的训练要困难得多。浮点非结合性、CUDA 非确定性以及进程顺序都在与可复现性作对。

**解药**：从第一天起就投入可复现性。控制随机种子、固定集合操作顺序，并在可能时使用确定性算法。

## 未来方向

这个领域演进迅速。若干趋势将塑造下一代系统：

### 趋势 1：从横向扩展回到纵向扩展

在数千块 GPU 上训练会引入单节点训练所没有的通信开销。硬件趋势（更大的 GPU 内存、更快的互连、芯粒设计）让在更少但更强的节点上训练成为可能。

极端情形：**在单块超大规模加速器上训练整个模型**。这消除了所有分布式系统的复杂性——但需要根本不同的硬件。

### 趋势 2：异构计算

当前系统假设同构 GPU。未来的系统可能混合：

- 不同代际的 GPU
- GPU 与其他加速器（TPU、定制 ASIC）
- 用于稀疏操作的 CPU 计算
- 解耦内存池

异构调度是一个开放的研究问题。

### 趋势 3：弹性训练

当前系统需要固定的 GPU 数量。弹性训练可以在不停止的情况下增减 GPU：

- 资源可用时扩容
- 被抢占时缩容
- 在部分故障下继续运行

这需要动态的并行重配置和健壮的检查点（checkpoint）机制。

### 趋势 4：通信感知架构

模型架构将越来越多地与通信模式协同设计：

- 通信最优路由的专家混合
- 最小化跨设备通信的注意力模式
- 匹配硬件层级的分层模型

「ML 研究」与「系统研究」之间的区分将继续模糊。

### 趋势 5：自动并行化

手动配置并行是专家密集型的工作。自动系统有望：

- 在给定硬件约束下搜索并行策略
- 把模型编译为分布式执行
- 自动优化通信模式

早期系统（Alpa、FlexFlow、TensorFlow 的 DTensor）显示出潜力，但对前沿模型而言，手动调优仍然胜出。

## 数学世界观

本书的书名——*The Algebra of Distributed Training*——是有意为之。我们把分布式训练当作一门数学学科，而不是一袋技巧。

**集合操作构成一个群**：七个原语按照规则组合与复合。AllReduce = ReduceScatter ∘ AllGather 不是技巧——它是定理。

**并行策略构成一个格**：策略可以按内存消耗和通信量排序。格结构揭示了合法的转换。

**效率有界**：屋顶线模型、带宽下界和流水线气泡比例设定了理论极限。这些界指导优化。

**扩展服从定律**：幂律支配模型质量、计算效率和硬件利用率。这些定律使预测成为可能。

这个数学基础带来两件事：

1. **迁移**：理解一个系统有助于理解其他系统
2. **预测**：新系统可以在实现之前就被分析

懂得代数的工程师能推理从未见过的系统。只懂具体配置的工程师在配置变化时就会迷失。

## 结语

分布式训练已经从一项运维挑战转变为核心能力。构建前沿 AI 系统需要深入理解计算如何在硬件间分布。

本书提供了基础、策略和案例研究。但这个领域发展很快——新硬件、新架构、新技术不断涌现。我们建立的数学框架让你能批判性地参与这些发展。

目标不是记住 FSDP 配置或 NCCL 算法。目标是理解某些配置**为什么**有效、**何时**会失效。这种理解使你能：

- 调试新奇的系统
- 设计新的并行策略
- 评估新硬件
- 预测训练效率

分布式训练是理论计算机科学、系统工程与机器学习交汇之处。它奖励对这三个学科的深入理解。

代数优美，系统精巧。它们所赋予的能力——训练理解语言、生成图像、推理世界的模型——是变革性的。

我们希望本书成为你自己探索的基础。

## 结课练习

这些练习整合了全书的概念：

1. **系统设计**：你需要在 512 块 80GB H100 上训练一个 175B 参数的稠密 transformer。设计并行策略，估算每 GPU 内存，计算预期 MFU，并找出可能的瓶颈。

    ??? hint "思路"
        从内存入手：$16\Psi = 2.8$ TB 静态。仅模型状态就需要至少 35 块 GPU，所以需要 ZeRO-3 或 3D 并行。试试 TP=8（节点内）、PP=8（64 层 / 8 阶段）、DP=8（512/64）。检查每微批（micro-batch）的激活内存。由 $m$ 个微批估算气泡比例。通信：TP 占主导（第 13 章公式），DP AllReduce 可以重叠。初始目标 MFU 约 35–40%。

2. **架构分析**：一个新模型提出「局部注意力」，每个 token 只关注 256 个邻近 token。分析这对分布式训练的影响：它如何影响张量并行？流水线并行？哪些通信模式会改变？

    ??? hint "思路"
        局部注意力消除了 $O(S^2)$ 激活内存项——它变成 $O(S \cdot w)$，其中 $w=256$。这大幅降低内存压力（第 19 章），使更长的序列无需 CP 即可行。对 TP：由于线性投影未变，注意力 AllReduce 量保持不变（$BSH$）。对 PP：阶段边界上的激活更小。关键收益：对中等 $S$，上下文并行（第 17 章）变得不再必要。

3. **容错**：你为期 2 周的训练运行平均每 3 天因硬件问题失败一次。设计一个容错策略，包括检查点频率、恢复时间，以及作为训练时间一部分的总开销。

    ??? hint "思路"
        MTBF = 3 天 = 259,200s。使用 Young/Daly 公式：$I^* = \sqrt{2 T_{\text{ckpt}} / \lambda}$，其中 $\lambda = 1/\text{MTBF}$。若异步检查点耗时 5 分钟（$T_{\text{ckpt}} = 300$s）：$I^* = \sqrt{2 \times 300 \times 259200} \approx 12,470$s $\approx 3.5$ 小时。14 天内预期失败约 4.7 次。每次故障的恢复时间：检查点恢复（约 5 分钟）+ 丢失的工作（平均约 1.75 小时）。总开销：检查点写入（5 分钟/3.5 小时 $\approx$ 2.4%）+ 恢复（约 4.7 × 1.8 小时 / 336 小时 $\approx$ 2.5%）。预算约 5% 总开销。

4. **新奇硬件**：一款新加速器相比 H100 提供 2× FLOPs 但 0.5× 内存带宽。这如何改变最优并行策略？哪些操作会成为瓶颈？

    ??? hint "思路"
        屋顶点移动：$I_{\text{ridge}} = F/\beta$。在 2× FLOPs 与 0.5× 内存带宽下，内存屋顶点高 4 倍——更多操作变为内存受限。注意力、LayerNorm、逐元素操作都会更严重地撞上内存上限。最优应对：更多内核融合、激进重算（用便宜 FLOPs 换内存带宽）、更大的 TP 度以减少每 GPU 激活大小，以及用 FP8 将内存流量减半。网络屋顶点也翻倍——DP 需要更大的批才能保持计算受限。

5. **扩展预测**：你在 64 块 GPU 上用 1 周训练了一个 7B 模型。假设理想扩展，在 640 块 GPU 上训练 70B 模型需要多久？哪些因素会让实际时间超过这一估计？

    ??? hint "思路"
        理想：$T = 6\Psi D / (P \cdot F \cdot \text{MFU})$。若 MFU 相同且采用 Chinchilla 最优的 $D \propto \Psi$：计算按 $\Psi^2$ 扩展，而 GPU 按 10× 扩展。因此 $T_{\text{ideal}} = 7 \times (70/7)^2 / 10 = 70$ 天。现实会超过这一估计，因为：(1) 640 块 GPU 上 MFU 下降（通信更多），(2) 70B 需要 TP/PP，增加气泡/通信开销，(3) 更大的批可能超过 $B_{\text{crit}}$，(4) 大规模下的故障恢复。预期为理想的 1.5–2×。

6. **经济优化**：GPU-小时成本 \$3。以最优批大小把 13B 模型训练到目标损失需要 100K GPU-小时。把批大小翻倍会使收敛慢 20%。在什么 GPU-小时价格下，更大批次尽管收敛更差仍具成本效益？

    ??? hint "思路"
        小批：100K GPU-小时，成本 = 100K × $R$。大批（2×）：每步 FLOPs 相同但步数多 20% → 120K GPU-小时的计算。然而（若低于 $B_{\text{crit}}$）大批把实际耗时减半——只在时间受限场景中相关。成本比较：120K × $R$ vs 100K × $R$。在纯 GPU-小时成本上，大批**永远**不会更便宜。只有实际耗时具有价值时（例如机会成本、截止日期）它才胜出。若截止日期的价值 $> 0.2 \times 100K \times R$，大批胜出。

7. **对比分析**：在以下方面比较 LLaMA 3 405B、DeepSeek-V3 671B 和 Mixtral 8x22B：(a) 推理时每 GPU 内存，(b) 每次前向的 FLOPs，(c) 在 1024 块 H100 上的预期训练吞吐。哪个训练最高效？哪个推理最高效？

    ??? hint "思路"
        (a) 推理内存（FP16）：LLaMA 405B → 810 GB（约 11 块 H100）；DeepSeek 总计 671B 但激活 37B → 总计 1.34 TB 但可卸载（offloading）非激活专家；Mixtral 8×22B = 总计 176B，激活 44B → 352 GB。(b) 每 token FLOPs：LLaMA $2 \times 405B$；DeepSeek $2 \times 37B$（MoE）；Mixtral $2 \times 44B$（MoE）。(c) 训练：DeepSeek 的 MoE + FP8 给出每 GPU 最高的 tokens/s；LLaMA 405B 需要最多的通信。**训练最高效**：DeepSeek（FP8 + 稀疏）。**推理最高效**：Mixtral（激活参数最少，占用 GPU 最少）。

- 构建并开源这些系统的 Google、NVIDIA、Microsoft、Meta 和 Anthropic 团队
- 奠定理论基础的学术研究者
- 在网上记录经验的实践者
- PyTorch、JAX 及相关项目周围的开源社区

科学通过共享知识而进步。我们希望本书能为这一传统做出贡献。

## 关键要点

1. **第一性原理可以扩展**：代数性质可预测每一种并行策略。
2. **系统思维是必需的**：内存、计算和通信共同约束性能。
3. **调查胜过配方**：最好的配置是推导出来的，不是背下来的。
